# 交付前的独立检查（必做）

做的人不给自己打分。所有交付物（HTML、Word、配图、生图prompt.md、封面生图prompt.md）交给用户之前，都要走一遍这个检查环。

## 谁来查

- 在 Claude 里：开一个新的子代理，它没看过制作过程。只给它成品文件、原文、改动清单（用户要求改过字时，列出从什么改成什么）和下面的检查表，让它逐项判断通过或不通过，并给出证据。它只报告，不改文件。不能开子代理时，按下面 Codex 的做法单独跑一轮检查。
- 在 ChatGPT Work 或 Codex 里：如果能开子代理就同样做；不能的话，制作完成后单独跑一轮检查，只看成品、原文和检查表，不参考制作时的判断。

## 检查表

能用脚本量的，都用脚本量。

| 检查项 | 怎么查 | 通过标准 |
|---|---|---|
| 结构 | `python3 scripts/selfcheck.py 成品.html 标记稿.txt`（只要 Python） | PASS：只用内联样式，每段尾字锁定（锁住的部分除去英文单词不多出 12 个字），图片已嵌入，有版本号，没有破折号，正文和标记稿一字不差。还没换成图的占位框会打印 WARNING，交付时列给用户 |
| 断行 | 有浏览器时 `python3 scripts/htmlcheck.py 成品.html` | 340 到 450px 的每一种手机宽度、四组字体，TOTAL issues 0。没有浏览器时以 selfcheck 的尾字锁定为准，并在结果表里写明没跑浏览器检查 |
| 专有名词和字距 | 有浏览器时 `python3 scripts/phonecheck.py 成品.html`（402 小屏和 440 大屏） | 人名和 Genie 4 这类带空格的英文名不拆到两行，尾行没有单字，没有字距明显变松的行，结果是 PASS；为字距改过的措辞都列在改动清单里 |
| 正文和原文一致 | 标记稿和原文逐段比对，不换行空格 U+00A0 按普通空格算 | 只有标题替换（原文里「第 X 层」一类的分层句换成小标题）；新增的竖线标题、小标题和结尾的「全文完」不算差异。不为断行改字 |
| 复制按钮和版本号 | 打开页面看 | 有复制按钮，文件名带 `_vN`，页面上标「第 N 版」 |
| 嵌入的图片 | 把 base64 解出来和图片文件比哈希 | 逐字节一致 |
| 间距 | 按 SKILL.md 第 3 节的量法；有用户截图时量截图 | 符合第 3 节的比例，误差 ±0.05；没有截图时，CSS 数值和第 2 节一致 |
| 对齐 | 手机宽度截图 | 两端对齐没有把字拉散，长英文段落是左对齐 |
| 版式元素 | 手机宽度截图 | 竖线和字差不多高、标题里的 AI 是黑色加粗、分隔线渐隐、引用块和水滴引号、红色斜体「全文完」 |
| 图片位置 | 看图片前后的段落 | 开头以文字为主，每张图紧跟它解释的那句话，两张图之间至少 3 段 |
| 配图尺寸和边距 | 量最外面笔画到四边的像素 | 宽 1080；上下 64px（±4px）；左右 64px，居中的图较宽一侧 64px |
| 配图字号 | 量各类文字的笔画实际高度 | 符合 `references/images.md` 第 4 节，没有缩字 |
| 配图可读性 | 把图缩到 330px 宽看 | 主标签和 17px 正文差不多大，辅助说明不用放大也能看清 |
| 配图内容 | 看图、逐字核对 | 图形形式符合概念（循环是圆环）；圆环图居中、标题在圈正中、步骤标签在圈外紧挨圆点；手绘效果；没有错字、乱码、多余英文；只用规定的颜色 |
| 生图prompt.md | 用 diagram.py 或 wireframe.py 按坐标重排一遍 | 文字放得下、不压线、边距正确；文字和原文一致；没有引用用户看不到的附图 |
| 封面 | 看图或封面生图prompt.md、封面对比图 | 和内文配图分开交付；四张，两两至少两个维度不同，最多一张用左字右图；每张有一句构思说明它怎么回答标题；标题逐字正确，缩到 358px 宽仍看得清；1:1 方框里主体完整；配色和参考封面一致；没有真人的脸 |

## 环

1. 检查方给出结果表。
2. 有不通过的项，就回到对应的步骤修改，修完再查一遍。
3. 最多 3 轮。3 轮后还有不通过的，停下来，告诉用户卡在哪一项、为什么、有什么选择，不硬交。
4. 交付时附一张简短的检查结果表：检查项、结果、证据。
